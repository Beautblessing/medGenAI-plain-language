# Workspace 2: Narrative Release Review and Sign-off

Code: `narrative_review.py`, `narrative_freeze.py`, `narrative_review_ui.py`.
Local state: `runtime_narrative_review/` (append-only logs).

## 1. Purpose

The reference narratives were generated by a model, so they need a human check before they are used as
the evaluation baseline. In this workspace a named reviewer reads each of the 40 texts next to the
approved structured record, records a decision, corrects texts that need it, and freezes the signed-off
release. Workspace 3 then reports, on every run, whether its reference texts are signed off and frozen.

This workspace reads the approved version 9 reference read-only and never changes it or the release file.

## 2. Inputs

- The narrative release (Dataset 2i, `reference_narratives/`, SHA-256 `374910b8…e120`): 40 texts =
  10 patients × English/Spanish × professional clinical narrative and patient explanation.
- The approved version 9 record of each patient and its documented limitations (from Workspace 1).

## 3. Tabs

| Tab | What happens |
| --- | --- |
| Review Narratives | Pick patient and language. The professional narrative and patient explanation are shown side by side with the automatic checks, the approved structured record and its limitations. Record a decision with reviewer name and role: **Approved**, **Approved with comments** or **Needs revision** (a comment is required unless Approved). Each decision is bound to the SHA-256 of the exact text |
| Review Narratives → correction panel | For a text marked Needs revision: "Suggested passages to check" splits the instruction into numbered issues, highlights the likely sentences and suggests an action (Replace, Remove, Add, Merge). Edit the text, preview the word changes in red and green, and save a corrected version with editor, role and reason |
| Sign-off Status | Coverage of the whole release; "Narrative release signed off" when all 40 current texts are approved. Download all decisions as CSV |
| Freeze and Download | Shows the freeze status (not frozen, matches freeze, changed since freeze, sign-off changed since freeze). "Create freeze" writes a verified, immutable ZIP; if nothing changed, the existing freeze is reused |

## 4. Rules

- Decisions are append-only; the latest decision for an exact text hash counts.
- A corrected text has a new hash and needs a fresh decision. Corrections are logged with the new text,
  its SHA-256, a word diff, the decision answered, the editor and the reason.
- An approved correction becomes the evaluation reference for that text; the release file is not changed.
- The app records who decided; it does not verify credentials.
